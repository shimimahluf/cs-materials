מה בונים בשני החלקים

את המחלקות של המסעדה כתבתם במטלה הקודמת. עכשיו מחברים אותן לחלון WPF אחד: תפריט בטבלה, הזמנה ברשימה, כפתורים, והוספת פריטים חדשים לתפריט. בחלק הזה מכינים את המחלקות, בונים את החלון, ומציגים בו את התפריט.

החלון שבונים

השמות הכחולים הם ה-x:Name של כל פקד. השתמשו בדיוק בשמות האלה, כי הקוד בדף מתייחס אליהם.

שפת הממשק: הטקסטים בחלון באנגלית, כמו בגרסת המסוף, כדי שתוכלו להשוות לדוגמאות בדף אחד-לאחד. אם תרצו חלון בעברית, אפשר בסוף (משימת בונוס).

תזכורת

קראו, ואז ענו על הבוחן הקצר שבסוף. בשלבים יש קישורים חזרה לכאן.

המרת טיפוסים: למעלה ולמטה

עצם מטיפוס Drink הוא גם MenuItem, ולכן אפשר להחזיק אותו במשתנה מטיפוס MenuItem. השאלה היא תמיד דרך איזה "משקפיים" הקומפיילר מסתכל על העצם: הוא מכיר רק את מה שיש בטיפוס של המשתנה.

Casting reminder
// Up-casting: automatic and always safe
MenuItem item = new Drink("Lemonade", 14, true);

Console.WriteLine(item.GetPrice());   // 18 - virtual, so Drink's version runs
// Console.WriteLine(item.IsLarge);   // compile error: item is a MenuItem variable

// Safe down-casting: check with "is", and only then cast
if (item is Drink)
{
    Drink drink = (Drink)item;
    Console.WriteLine(drink.IsLarge);  // true
}

// Unsafe down-casting: compiles, but crashes when the program runs
Dish dish = (Dish)item;                // InvalidCastException
שימו לב: כדי לקרוא לפעולה וירטואלית כמו GetPrice() לא צריך להמיר. ההמרה למטה נחוצה רק כשרוצים להגיע למשהו שקיים רק במחלקה היורשת, כמו IsLarge.

ב-C# אפשר גם לבדוק ולהמיר בשורה אחת: if (item is Drink drink). מותר להשתמש בצורה הזו, אבל במטלה נכתוב את הצורה המלאה כדי שהשלבים יהיו ברורים.

איפה זה פוגש אותנו ב-WPF

כשבוחרים שורה ב-DataGrid, המאפיין SelectedItem מחזיר את העצם שנבחר, אבל הטיפוס שלו הוא object. הטבלה לא יודעת שהיא מציגה פריטים של מסעדה. לכן תמיד בודקים ואז ממירים:

SelectedItem
if (menuGrid.SelectedItem is MenuItem)
{
    MenuItem item = (MenuItem)menuGrid.SelectedItem;
    // ... use item
}

יתרון נוסף: כששום שורה לא נבחרה, SelectedItem הוא null, ו-is מחזיר false עבור null. בדיקה אחת מגינה משני המקרים.

מעבירים ומעדכנים את המחלקות

כ-15 דקות
עיקרון: כימוס

בסוף השלב: הפרויקט החדש עובר קומפילציה עם המחלקות שלכם, והמחלקות כבר לא מדפיסות כלום בעצמן.

צריכים תזכורת?כימוס

פרויקט חדש

  1. צרו פרויקט חדש מסוג WPF Application.
  2. הוסיפו לפרויקט את המחלקות מהמטלה הקודמת (Project > Add > Class), והעתיקו אליהן את הקוד שלכם.
  3. בכל קובץ מחלקה, שנו את שורת ה-namespace כך שתהיה זהה ל-namespace שמופיע ב-MainWindow.xaml.cs.
למה ה-namespace חשוב כאן: ל-WPF יש מחלקה משלה בשם MenuItem (פריט בתפריט נפתח של חלון). אם המחלקות שלכם יישארו ב-namespace אחר, הקומפיילר לא יידע לאיזה MenuItem התכוונתם ויציג שגיאה. כשהן באותו namespace כמו החלון, שלכם מנצחת.

מחיר: שלושה חברים, שלושה תפקידים

שלושה חברים במחלקה קשורים למחיר, ולכל אחד תפקיד אחר. השם של כל אחד מסביר מה הוא עושה:

חבר במחלקהמה זהתפקיד
BasePriceמאפיין עם get ו-set, לא וירטואליהמחיר הבסיסי שנשמר. ה-set שומר רק ערך חיובי (כימוס)
GetPrice()פעולה וירטואלית, נדרסת ב-Drink וב-Dessertמחשבת את המחיר הסופי, כל סוג בדרך שלו (רב-צורתיות)
FinalPriceמאפיין לקריאה בלבד, לא וירטואלימחזיר את GetPrice(). קיים רק כדי שהטבלה תוכל להציג אותו, נבין למה בשלב 2
  1. אם במטלה הקודמת המאפיין נקרא Price, שנו את השם שלו ל-BasePrice. הכי בטוח: קליק ימני על השם ובחירה ב-Rename, כך שכל המקומות שמשתמשים בו יתעדכנו.
  2. ודאו ש-GetPrice() מוגדרת virtual ב-MenuItem, ונדרסת ב-Drink וב-Dessert. זה החבר הווירטואלי היחיד שקשור למחיר.
  3. הוסיפו ל-MenuItem את המאפיין FinalPrice (קוד בהמשך).
מי שהגדיר במטלה הקודמת את המאפיין כ-virtual: ב-C# גם מאפיין יכול להיות וירטואלי, אז זה עבד. אבל שני חברים שאפשר לדרוס לאותו דבר זה מתכון לבלבול. בוחרים מקום אחד לחישוב, GetPrice(), ומוחקים את virtual ו-override מהמאפיין BasePrice.

בלי Console בתוך המחלקות

בתוכנית עם חלון אין מסוף, ולכן כל Console.WriteLine בתוך המחלקות פשוט לא יוצג. העיקרון: המחלקות שומרות על הנתונים ועל הכללים, והחלון מחליט איך לדבר עם המשתמש.

  1. ב-set של BasePrice: ערך לא תקין פשוט לא נשמר. בלי הדפסה.
  2. ב-AddItem וב-RemoveItem: בלי הדפסות. הן כבר מחזירות false כשמשהו לא בסדר, והחלון יבדוק את זה.

למה אין עמודה IsLarge? הרשימה היא List<MenuItem>. כל משקה שהוכנס אליה עבר המרה כלפי מעלה ל-MenuItem, והטבלה מסתכלת על כל השורות דרך "המשקפיים" של MenuItem. היא מכירה רק את המאפיינים שלו. IsLarge עדיין קיים בעצם, בדיוק כמו בשאלה 2 בבוחן, אבל לא נראה דרך הפניה מטיפוס MenuItem.

למה צריך את FinalPrice? הטבלה מציגה רק מאפיינים, לא פעולות, ולכן את GetPrice() היא לא הייתה מציגה. FinalPrice עצמו לא וירטואלי, אבל הוא קורא ל-GetPrice() שכן וירטואלית, ולכן עוגת התפוחים מקבלת 34 והלימונדה הגדולה 18.

ושימו לב לשתי הלימונדות: בטבלה אי אפשר לדעת מה ההבדל ביניהן חוץ מהמחיר. את זה נפתור בשלב הבא.

המרה כלפי מטה, בצורה בטוחה

בסוף השלב: בחירת שורה בטבלה מציגה מתחת לטבלה את פרטי הפריט, כולל מה שקיים רק בסוג שלו.

צריכים תזכורת?המרה כלפי מטהSelectedItem

כשהמלצר בוחר שורה בטבלה, detailsText מציג את פרטי הפריט, כולל המידע שקיים רק בסוג שלו. כתבו את הפעולה menuGrid_SelectionChanged:

  1. אם SelectedItem אינו MenuItem (כולל המקרה שלא נבחר כלום), הציגו Select an item to see its details. וצאו מהפעולה.
  2. אחרת, המירו ל-MenuItem והתחילו מחרוזת: השם, המחיר הבסיסי והמחיר הסופי (ראו פלט לדוגמה).
  3. הוסיפו לפי הסוג: למנה vegetarian: yes/no, למשקה size: large/small, לקינוח ice cream: yes/no.
  4. לפני כל המרה כלפי מטה בודקים עם is.

שאלה למחשבה: מה יקרה בלי הבדיקה?

נסו לרגע לכתוב רק Drink drink = (Drink)item; בלי if (item is Drink), הריצו ובחרו את השניצל.

התוכנית תיפול עם InvalidCastException. הקומפיילר הסכים, כי MenuItem יכול להיות Drink. רק בזמן הריצה מתגלה שהעצם הזה הוא בכלל Dish. בגלל זה בודקים לפני כל המרה כלפי מטה. אחרי הניסוי החזירו את הבדיקה.

menuGrid_SelectionChanged skeleton
private void menuGrid_SelectionChanged(object sender, SelectionChangedEventArgs e)
{
    if (!(menuGrid.SelectedItem is MenuItem))
    {
        detailsText.Text = "Select an item to see its details.";
        return;
    }

    MenuItem item = (MenuItem)menuGrid.SelectedItem;
    string details = item.Name + " | base " + item.BasePrice + " NIS | final " + item.GetPrice() + " NIS";

    if (item is Dish)
    {
        Dish dish = (Dish)item;
        details += " | vegetarian: " + (dish.IsVegetarian ? "yes" : "no");
    }
    // TODO: Drink, Dessert

    detailsText.Text = details;
}
