מסעדה, חלק 1: פריטי התפריט

במטלה הזו תבנו מאפס אפליקציית מסוף ב-C# שמנהלת הזמנות במסעדה. בחלק הראשון בונים את פריטי התפריט: מחלקת בסיס, שלושה סוגי פריטים, ומחיר שכל סוג מחשב בדרך שלו.

  • זמן משוער: כשעה, בקצב שלכם
  • שפה: C#, אפליקציית Console
  • הגשה: בסוף חלק 2

מה בונים בשני החלקים

מערכת שמלצר משתמש בה: הוא רואה את התפריט, מוסיף פריטים להזמנה, מוחק פריט שהוזמן בטעות, וסוגר את ההזמנה עם קבלה וסכום לתשלום. בחלק הזה בונים את המחלקות שמסומנות בקו מלא בתרשים. את Order (במקווקו) ואת התוכנית הראשית בונים בחלק 2.

חץ עם משולש ריק: ירושה קו עם מעוין ריק: צבירה (ההזמנה מחזיקה פריטים) מקווקו: נבנה בחלק 2
שפת הפלט: את כל ההדפסות למסוף כתבו באנגלית. מסוף Windows מציג עברית הפוכה או כסימני שאלה, והפלט לדוגמה בדף כתוב באנגלית כדי שתוכלו להשוות אליו אחד-לאחד.
איך לעבוד: צרו פרויקט Console App חדש. אפשר לכתוב את כל המחלקות בקובץ Program.cs אחד, או כל מחלקה בקובץ משלה. בכל שלב כתוב בהתחלה מה אמור לעבוד בסופו. נסו לפתור לבד, ופתחו רמז רק אחרי כמה דקות של תקיעה. אם לא ברור מה מבקשים, חזרו לתזכורת דרך הקישורים שבכל שלב.

תזכורת קצרה

קראו, ואז ענו על הבוחן הקצר שבסוף. בשלבים יש קישורים חזרה לכאן.

1

כימוס (Encapsulation)

התכונות של המחלקה מוסתרות (private), והגישה אליהן עוברת דרך מאפיינים או פעולות שהמחלקה שולטת בהם. כך אף אחד מבחוץ לא יכול לשים במחיר של מנה ערך שלילי.

MenuItem.cs
private double basePrice;

public double BasePrice
{
    get { return basePrice; }
    set
    {
        if (value > 0)
            basePrice = value;   // only valid values get in
    }
}

2

ירושה (Inheritance)

מחלקה יורשת מקבלת את כל מה שיש במחלקת הבסיס ומוסיפה משלה. משקה הוא פריט בתפריט, ויש לו גם גודל. הבנאי של המחלקה היורשת מעביר את הנתונים המשותפים לבנאי של הבסיס בעזרת base.

Drink.cs
class Drink : MenuItem
{
    private bool isLarge;

    public Drink(string name, double basePrice, bool isLarge)
        : base(name, basePrice)
    {
        this.isLarge = isLarge;
    }
}
3

רב-צורתיות (Polymorphism)

פעולה שמוגדרת virtual במחלקת הבסיס יכולה להיות מוחלפת (override) במחלקה היורשת. כשקוראים לפעולה דרך הפניה מטיפוס הבסיס, מתבצעת הגרסה של הטיפוס האמיתי של העצם.

Example
// in MenuItem
public virtual double GetPrice() { return basePrice; }

// in Drink
public override double GetPrice()
{
    if (isLarge)
        return base.GetPrice() + 4;
    return base.GetPrice();
}

MenuItem item = new Drink("Lemonade", 14, true);
Console.WriteLine(item.GetPrice());   // 18 - Drink's version runs

תזכורת: List<T>

רשימה היא כמו מערך שגדל ומתכווץ לבד. נשתמש בה כדי להחזיק את התפריט.

List reminder
using System.Collections.Generic;   // needed at the top of the file

List<MenuItem> menu = new List<MenuItem>();   // empty list

menu.Add(new Dish("Schnitzel", 58, false));    // add to the end
menu.Add(new Drink("Lemonade", 14, true));

Console.WriteLine(menu.Count);                 // how many items: 2
Console.WriteLine(menu[0].Name);               // access by index, like an array

menu.RemoveAt(1);                              // remove by index

// foreach: go over every item, no index needed
foreach (MenuItem item in menu)
{
    Console.WriteLine(item);
}

// for: when you need the index (e.g. to print numbers)
for (int i = 0; i < menu.Count; i++)
{
    Console.WriteLine((i + 1) + ". " + menu[i]);
}
שימו לב: בתוך לולאת foreach אסור להוסיף או להסיר פריטים מהרשימה שעליה עוברים.

בוחן בדיקה עצמית

השלבים

הזמנים ליד כל שלב הם הערכה בלבד, לא מגבלה. סמנו כל שלב שסיימתם, וההתקדמות תופיע בפתק בצד.

1

מחלקת הבסיס MenuItem

כ-15 דקות
עיקרון: כימוס

בסוף השלב: יש לכם מחלקה אחת, MenuItem. היא יודעת להדפיס את עצמה, והיא לא מסכימה לקבל מחיר שלילי.

צריכים תזכורת?כימוסתקציר: מחלקה ועצם (PDF)
  1. שתי תכונות פרטיות: name (מחרוזת) ו-basePrice (ממשי).
  2. בנאי שמקבל שם ומחיר בסיסי.
  3. מאפיין Name לקריאה בלבד (רק get).
  4. מאפיין BasePrice עם get ו-set. ה-set מקבל רק מחיר חיובי. אם הערך לא תקין, הדפיסו Error: price must be positive. Price not changed. ואל תשנו את המחיר.
  5. גם הבנאי צריך לעבור דרך הבדיקה, כך שלא ייווצר פריט עם מחיר שלילי. אם המחיר שהתקבל לא תקין, המחיר יהיה 1.
  6. פעולה GetPrice() שמחזירה את המחיר.
  7. דריסה של ToString() שמחזירה מחרוזת בפורמט Falafel - 30 NIS. השתמשו ב-GetPrice() ולא ישירות ב-basePrice, זה יהיה חשוב בשלב 3.

רמז 1

כדי שהבנאי ייהנה מהבדיקה, אל תכתבו בו this.basePrice = basePrice. במקום זה תנו למחיר ערך ברירת מחדל 1, ואז השמו דרך המאפיין: BasePrice = basePrice;. אם הערך תקין, הוא ידרוס את ה-1.

למה override ב-ToString? כל מחלקה ב-C# יורשת בשקט מהמחלקה object, שכבר יש לה ToString וירטואלית. אתם מחליפים את הגרסה שלה.

2

שלושה סוגי פריטים

כ-20 דקות
עיקרון: ירושה

בסוף השלב: יש לכם שלוש מחלקות חדשות, מנה, משקה וקינוח. כל אחת יורשת מ-MenuItem, יש לה תכונה אחת משלה, והיא מדפיסה את עצמה בפורמט שלה.

צריכים תזכורת?ירושה

בנו שלוש מחלקות שיורשות מ-MenuItem. לכל אחת תכונה פרטית נוספת, בנאי שקורא ל-base, מאפיין לקריאה בלבד לתכונה החדשה, ודריסה של ToString().

מחלקהתכונה נוספתמה ToString() מחזירה
DishisVegetarian (bool)[Dish], אחריו התוצאה של base.ToString(), ובסוף (V) אם המנה צמחונית
DrinkisLarge (bool)[Drink], השם, הגודל בסוגריים (Large או Small), ואז המחיר
DessertwithIceCream (bool)[Dessert], אחריו base.ToString(), ובסוף + ice cream אם יש גלידה

ב-Drink אי אפשר להשתמש ב-base.ToString(), כי הגודל צריך להופיע באמצע. השתמשו במאפיין Name ובפעולה GetPrice(), שעברו בירושה.

שימו לב לפני שמריצים: בשלב הזה משקה גדול עדיין עולה כמו קטן, וגם הגלידה בחינם. זה מכוון. אל תוסיפו את התוספת למחיר באף מקום, גם לא ב-ToString(). נטפל בזה בשלב 3, בדרך הנכונה.

רמז 1

התכונות name ו-basePrice הן private במחלקת הבסיס, ולכן המחלקה היורשת לא יכולה לגשת אליהן ישירות. דרך הגישה היא המאפיינים הציבוריים Name ו-BasePrice.

לבחירת הגודל בשורה אחת אפשר להשתמש באופרטור התנאי: string size = isLarge ? "Large" : "Small";

רמז 2: שלד קוד ל-Dish
Dish skeleton
class Dish : MenuItem
{
    private bool isVegetarian;

    public Dish(string name, double basePrice, bool isVegetarian)
        : base(name, basePrice)

        this.isVegetarian = isVegetarian;
    }

    public bool IsVegetarian
    {
        get { return isVegetarian; }
    }

    public override string ToString()
    {
        string text = "[Dish] " + base.ToString();
        // TODO: add " (V)" when needed

}

מחיר שתלוי בסוג הפריט

כ-15 דקות
עיקרון: רב-צורתיות

בסוף השלב: משקה גדול וקינוח עם גלידה עולים יותר, והתוכנית מדפיסה תפריט של שמונה פריטים עם המחיר הנכון לכל אחד.

צריכים תזכורת?רב-צורתיותList<T>
  1. ב-MenuItem הפכו את GetPrice() לפעולה וירטואלית. רק את GetPrice(): המאפיין BasePrice נשאר כמו שהוא.
  2. ב-Drink דרסו את GetPrice(): משקה גדול עולה 4 ש"ח יותר מהמחיר הבסיסי.

מה קרה לעוגת התפוחים? ב-Dessert לא נגעתם ב-ToString() בשלב הזה. היא עדיין קוראת ל-base.ToString(), כלומר לקוד של MenuItem, ובכל זאת המחיר עלה מ-28 ל-34.

הסיבה: ToString() של MenuItem קוראת ל-GetPrice(), ו-GetPrice() וירטואלית. העצם הוא בפועל Dessert, ולכן מתבצעת הגרסה של Dessert, גם כשהקריאה מגיעה מתוך קוד של מחלקת הבסיס. זו רב-צורתיות, ובגלל זה ביקשנו בשלב 1 להשתמש ב-GetPrice() ולא ב-basePrice.
