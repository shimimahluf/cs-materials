צבירה (Aggregation)

עצם אחד מחזיק הפניות לעצמים אחרים שקיימים בפני עצמם. הזמנה מחזיקה פריטים מהתפריט, אבל היא לא יצרה אותם, והם ממשיכים להתקיים גם אחרי שההזמנה נסגרת. זה ההבדל מהרכבה (Composition), שבה העצם המוכל נוצר בתוך העצם המכיל ו"שייך" רק לו.

Example
MenuItem schnitzel = new Dish("Schnitzel", 58, false);  // lives on the menu

Order order = new Order(1);
order.AddItem(schnitzel);   // the order only points at the existing object

המחלקה Order

כ-25 דקות
עיקרון: צבירה (וגם כימוס)

בסוף השלב: יש לכם הזמנה שאפשר להוסיף אליה פריטים מהתפריט ולמחוק מהם, שיודעת לחשב סכום ולהדפיס קבלה, ושלא מסכימה להשתנות אחרי שנסגרה.

צריכים תזכורת?צבירהList<T>כימוס

הזמנה מחזיקה רשימה של פריטים מהתפריט. היא לא יוצרת פריטים חדשים, רק מקבלת הפניות לפריטים שכבר קיימים ברשימה menu.

  1. תכונות פרטיות: orderNumber (שלם), items מטיפוס List<MenuItem>, ו-isClosed (bool).
  2. בנאי שמקבל מספר הזמנה, יוצר רשימה ריקה, ומגדיר שההזמנה פתוחה.
  3. מאפיינים לקריאה בלבד: OrderNumber, IsClosed, ו-Count (כמה פריטים בהזמנה).
  4. bool AddItem(MenuItem item): מוסיפה את הפריט ומחזירה true. אם ההזמנה סגורה, מדפיסה Order is closed - cannot add items. ומחזירה false.
  5. bool RemoveItem(int position): מוחקת לפי מיקום שמתחיל ב-1 (כמו שהמלצר רואה במסך). אם ההזמנה סגורה, מדפיסה Order is closed - cannot remove items.. אם אין פריט במיקום הזה, מדפיסה No item at position X. (במקום X המיקום). בשני המקרים מחזירה false.
  6. double GetTotal(): סכום המחירים, בלולאת foreach שקוראת ל-GetPrice() של כל פריט.
  7. void PrintItems(): מדפיסה את הפריטים ממוספרים מ-1. אם ההזמנה ריקה, מדפיסה (order is empty).
  8. void Close(): סוגרת את ההזמנה.
  9. void PrintReceipt(): מדפיסה קבלה בדיוק בפורמט שבפלט לדוגמה.

בדיקה ב-Main (אחרי יצירת התפריט)

Main
Order order = new Order(1);
order.AddItem(menu[0]);   // Schnitzel
order.AddItem(menu[4]);   // Large lemonade
order.AddItem(menu[6]);   // Chocolate cake
order.PrintReceipt();

order.Close();
order.AddItem(menu[1]);   // should be refused

שאלה למחשבה: מה יקרה אם נעלה מחיר אחרי שהפריט כבר בהזמנה?

נסו: אחרי שהוספתם את menu[0] להזמנה, כתבו menu[0].BasePrice = 60; ורק אז הדפיסו קבלה. איזה מחיר יופיע לשניצל?

יופיע 60. ההזמנה לא שמרה עותק של השניצל אלא הפניה לאותו עצם בדיוק שנמצא בתפריט, וזו המשמעות של צבירה. במסעדה אמיתית הייתם שומרים בהזמנה את המחיר ברגע ההזמנה, אבל זה כבר עיצוב מתקדם יותר.

התוכנית הראשית: תפריט פעולות למלצר

כ-25 דקות
חיבור כל החלקים

בסוף השלב: התוכנית מציגה למלצר רשימת אפשרויות בלולאה, והוא יכול להוסיף, למחוק, להציג ולסגור הזמנות עד שהוא בוחר לצאת.

מחקו את קוד הבדיקה של שלב 4 (את יצירת התפריט השאירו), וכתבו לולאה שמציגה למלצר תפריט פעולות עד שהוא בוחר 0.

  1. כתבו פעולה סטטית PrintMenu(List<MenuItem> menu) במחלקה Program, שמדפיסה את הכותרת ---------- MENU ---------- ואחריה את הפריטים ממוספרים.
  2. פתחו הזמנה מספר 1 לפני הלולאה.
  3. בתחילת כל סיבוב הדפיסו שורת מצב: מספר ההזמנה, כמה פריטים יש בה, והסכום הנוכחי. אחריה הדפיסו את האפשרויות.
  4. 1 מציגה את התפריט. 2 מציגה את התפריט, שואלת מספר פריט ומוסיפה אותו להזמנה (מספר לא קיים: Invalid item number.). 3 מציגה את פריטי ההזמנה ושואלת איזה מיקום למחוק. 4 מציגה את ההזמנה.
  5. 5 סוגרת את ההזמנה, מדפיסה קבלה, ופותחת הזמנה חדשה עם המספר הבא. אי אפשר לסגור הזמנה ריקה (Cannot close an empty order.).
  6. 0 יוצאת ומדפיסה Goodbye!. כל מספר אחר: Unknown option.
