שדרוג המסעדה, חלק 1: מחלקה מופשטת

ממשיכים מהמסעדה שבניתם. בחלק הזה המחלקה MenuItem הופכת למופשטת, כל פריט יודע לאיזו עמדה במטבח הוא נשלח, ומוסיפים לתפריט סוג פריט חדש.

  • זמן משוער: כשעה, בקצב שלכם
  • שפה: C#, אפליקציית Console
  • הגשה: בסוף חלק 2

מתחילים מהמטלה הקודמת

פתחו את הפרויקט הגמור שלכם מהמטלה מסעדה: מערכת הזמנות במסוף. לפני שממשיכים, ודאו שיש בו:

  • המחלקה MenuItem והמחלקות Dish, Drink ו-Dessert שיורשות ממנה
  • המחלקה Order עם AddItem, GetTotal ו-PrintReceipt
  • ב-Main: הרשימה menu עם שמונת הפריטים, ותפריט הפעולות של המלצר

עוד לא סיימתם את המטלה הקודמת? סיימו אותה קודם: כל השלבים כאן בנויים עליה.

איך לעבוד: בכל שלב כתוב בהתחלה מה אמור לעבוד בסופו. הקוד שבבדיקות מחליף זמנית את הקוד של המלצר ב-Main: אל תמחקו את הקוד של המלצר, רק הפכו אותו להערה (/* ... */) עד שלב 6. הפלט כתוב באנגלית, כמו במטלה הקודמת.

תזכורת קצרה

קראו, ואז ענו על הבוחן הקצר שבסוף. בשלבים יש קישורים חזרה לכאן.

1

מחלקה מופשטת (Abstract class)

מחלקת בסיס שאי אפשר ליצור ממנה עצמים. היא מחזיקה את מה שמשותף למחלקות היורשות. במסעדה אין פריט שהוא "סתם פריט": כל פריט אמיתי הוא מנה, משקה או קינוח. לכן MenuItem מתאימה להיות מופשטת.

Example
abstract class MenuItem      // the word abstract before class
{
    // fields, a constructor, properties and methods - as usual
}

MenuItem a = new MenuItem("Falafel", 30);       // compile error
MenuItem b = new Dish("Schnitzel", 58, false);  // OK: a Dish is a MenuItem
List<MenuItem> menu = new List<MenuItem>();    // OK: a list of the base type
2

פעולה מופשטת (Abstract method)

פעולה שיש לה רק חתימה, בלי גוף. כל מחלקה יורשת חייבת לדרוס אותה עם override, אחרת הקוד לא מתקמפל. משתמשים בה כשלמחלקת הבסיס אין ברירת מחדל הגיונית. פעולה מופשטת יכולה להיות רק בתוך מחלקה מופשטת.

Example
// in MenuItem: a signature and ; - no body
public abstract string GetStation();

// in Drink: must override it
public override string GetStation()
{
    return "Bar";
}

MenuItem הופכת למופשטת

כ-15 דקות
עיקרון: הפשטה

בסוף השלב: אי אפשר יותר ליצור "סתם פריט" עם new MenuItem(...), וכל השאר עובד בדיוק כמו קודם: התפריט מודפס עם אותם מחירים.

צריכים תזכורת?מחלקה מופשטתתקציר: מחלקה ועצם (PDF)

לפני שמשנים: נחשו

עוד מעט תוסיפו את המילה abstract לפני class MenuItem. אילו מהשורות האלה יפסיקו להתקמפל? סמנו את כל מה שלדעתכם ייכשל.

Which lines break?
MenuItem m = new MenuItem("Falafel", 30);            // A
List<MenuItem> menu = new List<MenuItem>();         // B
menu.Add(new Dish("Schnitzel", 58, false));          // C
MenuItem drink = new Drink("Lemonade", 14, true);    // D
foreach (MenuItem item in menu)                      // E
    Console.WriteLine(item.GetPrice());

Compiler error
error CS0144: Cannot create an instance of the abstract type or interface 'MenuItem'

רק שורה A נכשלת. "מופשטת" אומר שאי אפשר ליצור עצם מהמחלקה עם new. אבל מותר להגדיר משתנה או רשימה מהטיפוס שלה, וזה בדיוק מה שהתפריט עושה: List<MenuItem> מחזיקה מנות, משקאות וקינוחים. גם קריאה ל-GetPrice() דרך MenuItem עובדת, ומתבצעת הגרסה של העצם האמיתי.

  1. הוסיפו את המילה abstract לפני class MenuItem.
  2. הריצו Build. אם בקוד שלכם נשארה יצירה של new MenuItem(...) (למשל הבדיקה משלב 1 במטלה הקודמת), הקומפיילר יסמן אותה. מחקו אותה או החליפו אותה ב-Dish.
  3. אל תשנו שום דבר אחר. הבנאי, המאפיינים ו-GetPrice() נשארים כמו שהם.

שאלה למחשבה: למה יש בנאי למחלקה שאי אפשר ליצור ממנה עצם?

הבנאי של MenuItem רץ בכל פעם שיוצרים מנה, משקה או קינוח: : base(name, basePrice) קורא לו. הוא שומר את השם ובודק את המחיר, כך שהקוד הזה כתוב פעם אחת בלבד.

אפשר אפילו להגדיר אותו protected במקום public: כך רק המחלקות היורשות יכולות לקרוא לו, וזה מבטא בדיוק את מה שהוא עושה.

רמז

השורה הראשונה של המחלקה צריכה להיראות כך: abstract class MenuItem. אם הקוד לא מתקמפל, קראו את הודעת השגיאה ולחצו עליה פעמיים: Visual Studio יקפוץ לשורה הבעייתית.

לאן שולחים כל פריט?

כ-20 דקות
עיקרון: פעולה מופשטת ורב-צורתיות

בסוף השלב: כל פריט יודע לאיזו עמדה הוא נשלח: מנה למטבח, משקה לבר, קינוח לעמדת הקינוחים. ההזמנה מדפיסה כרטיס לכל פריט, עם העמדה שלו.

צריכים תזכורת?פעולה מופשטתרב-צורתיות
  1. ב-MenuItem הוסיפו פעולה מופשטת public abstract string GetStation();.
  2. דרסו אותה בשלוש המחלקות: Dish מחזירה Kitchen, ‏Drink מחזירה Bar, ‏Dessert מחזירה Pastry.
  3. ב-MenuItem הוסיפו פעולה רגילה (לא מופשטת) string GetTicketLine() שמחזירה את העמדה בסוגריים מרובעים ואחריה את השם, למשל [Bar] Lemonade. היא קוראת ל-GetStation().
  4. ב-Order הוסיפו void PrintTickets(): שורת כותרת Order #1 tickets: (עם מספר ההזמנה), ואחריה שורה לכל פריט, עם שני רווחים בהתחלה ו-GetTicketLine().
שימו לב: מהרגע שהוספתם את הפעולה המופשטת ועד שדרסתם אותה בשלוש המחלקות, הקוד לא יתקמפל. זה מכוון: הקומפיילר מזכיר לכם מי עוד חסרה. קראו את הודעות השגיאה, אחת לכל מחלקה.

שאלה למחשבה: איך GetTicketLine() יודעת מה העמדה?

כשקוראים ל-GetStation() מתוך GetTicketLine(), מתבצעת הגרסה של העצם האמיתי. אם העצם הוא Drink, חוזר Bar. זו אותה רב-צורתיות שראיתם עם ToString() ו-GetPrice() במטלה הקודמת.

מחלקת הבסיס קובעת את מבנה השורה, וכל מחלקה יורשת משלימה רק את החלק שתלוי בה. נפגוש את הרעיון הזה שוב בקורס.

רמז 1

לפעולה מופשטת אין סוגריים מסולסלים: public abstract string GetStation();. ב-Drink הדריסה נראית כמו כל דריסה: public override string GetStation() ואחריה גוף עם return "Bar";.

GetTicketLine() צריכה שורה אחת: חיבור של "[", ‏GetStation(), ‏"] " ו-Name.
